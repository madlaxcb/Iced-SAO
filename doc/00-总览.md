# orb 项目总览

> 基于 iced 的「SAO 风格」UI 组件库。开发宿主 Linux，目标平台 Windows 10 22H2 / 11（交叉编译 + 验证机）。
> 计划书：`iced-sao-style-ui-dev-plan.md`（v0.2+）；环境报告：`doc/test-reports/env-2026-10-07.md`。

## 目录规则

| 目录 | 内容 | 版本控制 |
|---|---|---|
| `code/` | 源码（crates / apps / xtask / assets / .cargo） | 入库 |
| `dev/` | vendor、编译缓存、xwin 缓存、字体原件、验证机登记 | **忽略**（vendor 与 xwin-cache 需备份） |
| `doc/` | 计划书副本、ADR、设计规范、验证报告 | 入库 |
| `dist/` | 脚本生成的 Windows 产物与验证包 | **忽略** |

## 一次上手（断网可重复）

```sh
# 1. 进入开发环境（PATH + XWIN_CACHE_DIR）
source dev/env.sh

# 2. Linux 原生构建 / 运行（无显示服务时用 xvfb）
cd code
cargo build --offline --locked
cargo run --offline -p gallery            # 或 xvfb-run -a cargo run -p gallery

# 3. Windows 交叉构建（MSVC；CRT/SDK 缓存在 dev/xwin-cache）
cargo xwin build --offline --release --target x86_64-pc-windows-msvc -p gallery

# 4. 双目标检查（每次提交前；cfg(windows) 代码只有交叉检查能暴露问题）
cargo check --offline -p <pkg>
cargo check --offline --target x86_64-pc-windows-msvc -p <pkg>
```

## Windows 验证流程（W 关卡）

1. 交叉构建产物拷入 `dist/windows-verify/`（M1 起由 `xtask win-pack` 自动化）；
2. 同步到验证机，按 `doc/design/win-verify-checklist.md` 逐项验证；
3. 截图与结果回传 `doc/test-reports/win-verify/<日期>/`；
4. Windows 行为结论只以验证机为准；未验证项必须标注"未验证"。

## Workspace 结构

```
code/
├─ crates/  orb-tokens → orb-core → orb-theme → orb-widgets；旁支 orb-icons / orb-platform / orb-testkit
├─ apps/    gallery（陈列馆）、sample-launcher（示例应用）、probe（M0 预研，产品不含）
└─ xtask/   本地自动化（M1 实现 doctor / vendor / ci / win-check / win-pack / dist …）
```

依赖方向单向：`tokens → core → theme → widgets`；`cfg(windows)` 只允许出现在 `orb-platform`。

## 已知限制

- 本机（Linux 云 VM）无显示服务与真实 GPU：Linux 原生运行用 xvfb + 软件渲染替代，视觉判断以 Windows 验证机为准；
- `dev/vendor` 与 `dev/xwin-cache` 必须备份，丢失后无法离线重建；
- iced 0.14 API 基线：详见 ADR-005/006 中的事实清单。
