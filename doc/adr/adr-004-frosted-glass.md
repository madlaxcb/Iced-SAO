# ADR-004：毛玻璃策略

- 状态：**已接受（G1 伪毛玻璃为产品路线）**（2026-10-08，W0 判定）
- 关联：计划书 2.6、M0-P3、R3、ADR-003

## 背景

毛玻璃三条候选路线（计划书 2.6）：
- G1 伪毛玻璃：应用自持背景 + 预模糊副本 + 半透明白叠加 + 描边
- G2 整窗亚克力：`window-vibrancy`，DWM 对窗口背后桌面模糊
- G3 自定义着色器多遍模糊（首版即排除）

## W0 验证记录（用户 Windows 验证机）

| 轮次 | 形态 | 结果 |
|---|---|---|
| 第 1 轮 | 无边框 + 置顶 + 亚克力 | `acrylic applied`，但整窗纯黑不透明；壁纸不可见 |
| 第 2 轮 | **普通窗口**（系统边框、不置顶、不穿透）+ 亚克力 | 同样**纯黑背景**；且**拖动迟滞非常严重**（window-vibrancy 文档警告的已知性能问题实锤） |

## 决策

1. **G2 亚克力判定：在本验证机环境不可用**——`apply_acrylic` 调用成功但渲染纯黑（疑似 wgpu DX12 交换链与 DWM ACCENT 亚克力的合成问题），且拖动性能严重劣化。与官方文档提示的"拖动 / 缩放性能问题、与部分框架组合需验证"一致。
2. **产品路线：G1 伪毛玻璃**（计划书原推荐默认）：
   - 应用自持背景（壁纸 / 渐变），启动时生成预模糊副本，面板底部绘制对应区域 + 半透明白叠加 + 1px 高光描边；
   - 不依赖 DWM，跨后端（DX12 / tiny-skia）表现一致，性能可控，无黑块风险；
   - M3 实现 `BackgroundLayer` + 盒式模糊（`image` crate 或自写）。
3. G2 代码（`orb-platform::apply_acrylic_by_title`）保留为可选 feature（默认关闭），文档标注"在此类环境不可用"；不再投入验证成本。
4. 所有路线保留"纯半透明 + 描边"降级（计划书 1.4.6）。

## 影响

- M3 的 P3 原型重心改为 G1：预模糊副本与背景坐标系对齐（计划书 5.2"伪毛玻璃错位"项）；
- 窗口 `transparent` 设置仍保留于 acrylic 探测代码中（G2 feature 用），产品 Gallery / SampleLauncher 不依赖；
- 验证机 Windows 版本未登记（待 C.2），G2 失效根因（Win10 ACCENT vs Win11 Backdrop）不再深究。
